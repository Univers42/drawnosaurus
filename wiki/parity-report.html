What to build next

Ranked by how often someone would notice, against how much each one costs.

  1. Export the whole drawing as PNG, at a chosen scale, and copy it

    PNG export today saves the canvas as it is on screen: whatever is scrolled out of view is cut off, and the dialog's Scale and Transparent background controls are ignored. Rendering the scene to an offscreen canvas fixes that and opens the rest of the export gaps: transparent background, a selection or a single frame, and copy as PNG or SVG.

    ≈ 20 itemsengine export + dialog

  2. Paste plain text as text, and recognise pasted Mermaid

    Pasting text from anywhere else does nothing today. Excalidraw makes one text element per line, and hands Mermaid syntax to the Mermaid dialog. Both are small changes in the paste handler.

    4 itemshost paste path

  3. Write the tests for what is already built

    Copy, cut and paste by keyboard, Backspace, middle-mouse pan, Ctrl+O, menu arrow keys and the context-menu entries all work but no test drives them. About 25 items turn green without a line of product code.

    ≈ 25 itemstests only

  4. Elbow arrows

    The flowchart and architecture stories are what the templates show off, and straight connectors are the one visible compromise in them. Orthogonal routing over the existing fixed-point bindings, then cardinality arrowheads for ER diagrams.

    8 itemsengine routing

  5. A library of reusable pieces

    The largest single missing feature. The five templates are a catalogue to start from; a library lets people save their own selection and drop it back in, with ids regenerated and groups kept.

    18 itemsstorage + sidebar

Engine architecture

No named-action layer shared by shortcuts, menus and buttons (the palette has its own registry). No transaction API or branching history. Performance is benchmarked but nothing fails on a regression. No vector, matrix or circle primitives.

49

Export, clipboard, files

PNG is the on-screen canvas only, and the dialog's scale and transparent-background controls do nothing. No selection or frame export, no transparent background, no copy as PNG or SVG, no scene data inside an exported image. No .excalidraw import or export, no read-only link, export is always light-themed, and there is no crash-recovery store beyond the localStorage draft.

No search over text, labels or frame names, and no jump between matches.

Freehand and eraser

Strokes are smoothed and thin with speed, but a pen's own pressure is never read, pen, touch and palm are not told apart, and there is no point simplification. The eraser removes a whole stroke and never splits one.

Selection and locking

No Alt+click to reach a shape underneath another, no subtractive lasso, no on-canvas mark for a locked element or a group, and no Ctrl+Shift+L. The marquee has one mode, containment, which is deliberate.

Images

No crop, no replace, no broken-image state. Pictures live inside the board document, so two or three large ones reach MongoDB's 16 MB limit.

10

Frames, notes, embeds

Selecting a frame does not select its contents. A sticky note has no border colour. Embeds cannot be drawn as a region and have no loading or error state. An arbitrary shape cannot be turned into a flowchart node.

No stats panel, and position, size and angle cannot be typed as numbers.

Arrows and lines

No elbow arrows or ER arrowheads. Pressing the arrow key again does not cycle the arrow type. A label cannot be dragged along its arrow. A point cannot be removed while a line is being placed.

Collaboration and modes

No zen mode. Following someone works only inside presentation mode. Nobody can join read-only. Undo restores a whole element rather than only the properties you changed.

Plain-text paste makes nothing. Mermaid reads flowcharts only, with no preview before insert and no detection on paste.

Needs a harness first

  • An accessibility audit: focus traps, screen-reader labels, high contrast, reduced motion
  • The modifier matrix: every tool against Shift, Alt, Ctrl and their pairs
  • Host state kept in Svelte (menus, sidebar, collaboration) rather than in the engine

Different on purpose, and beyond Excalidraw

Different on purpose

  • The board lives on the server and merges per element; .osidraw files are an export, not the source of truth.
  • A marquee selects what it contains, never what it merely clips, so a small drag across a large background shape leaves it alone.
  • Select All includes locked elements so the context menu can unlock them; Excalidraw skips them.
  • Alt+Arrow moves between flowchart nodes, so it is not a fine nudge.
  • The cheat sheet's I for images and its Ctrl+Shift+]/[ are wrong; the oracle's own bindings are used.
  • No bold, italic or letter spacing, as in Excalidraw.
  • Hosted AI (text to diagram, wireframe to code) is not part of this project.

Not in Excalidraw at all

  • Figures: regular polygons, parallelogram, trapezoid, cylinder and document shapes, each with a label that follows the outline.
  • Presentation mode: frames as slides, a laser everyone can see, and late joiners landing on the current slide.
  • Five starter boards drawn with the real editor, with preview thumbnails.
  • Style presets that keep fonts, and a command palette covering every tool and figure.
  • Live gesture previews, per-element holds between editors, and encrypted live frames even on plain http://.
  • Sharing over the local network or the internet from one Share dialog.
